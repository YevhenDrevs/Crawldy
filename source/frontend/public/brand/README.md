# Бренд-файли Crawldy

Оригінали дизайнера лежать поза репозиторієм
(`Desktop/Проекти/Crawldy/Logo/`). Тут — веб-версії без жодних змін
самого знака:

- `crawldy-horizontal.png` — горизонтальний локап дизайнера
  (оригінал `crawldy_horizontal.png` 4348×876 → 1600×322, LANCZOS).
- `crawldy-vertical.png` — вертикальний локап дизайнера
  (оригінал `crawldy_logo.png` 4427×2398 → 1000×542).
- `crawldy-mark.png`, `crawldy-wordmark.png` — точні вирізки з
  горизонтального файлу по найширшому прозорому проміжку (299px між
  знаком і написом), потім даунскейл. Жоден піксель знака не змінено.

`crawldy-*.webp` — похідні від PNG, без втрат (пікселі ті самі, вага
вдвічі менша). Генерує `scripts/brand-webp.mjs`; після будь-якої зміни
PNG запустити його знову. Сторінки сайту показують WebP, а PNG лишаються
першоджерелом, запасним варіантом у `<picture>` і картинкою для
OG-картки (соцмережі WebP приймають не всі).

Компоненти — `app/components/Brand.tsx`: `Logo` (горизонтальний,
шапки), `LogoStacked` (вертикальний, вхід/каса/порожні стани),
`Logomark`/`Wordmark` (вирізки для тісних місць).

## Прозорість усередині літер

У вихідних файлах дизайнера замкнені області всередині «a» та «d» були
залиті непрозорим білим, а не прозорістю. На світлому тлі цього не
видно, на темному всередині літер світилися білі кружки. У
`crawldy_horizontal.png` дизайнера таких пікселів 93 347, у наших
похідних від 9 до 14 тисяч.

Виправлено 23 листопада 2026 у всіх чотирьох веб-файлах. Правилася лише
прозорість. Оскільки відомо, що фон під заливкою був білим, з кожного
пікселя відновлено частку покриття літерою, тобто розв'язано
    видиме_на_білому = c * колір_літери + (1 - c) * білий
і записано колір з прозорістю c. Завдяки цьому накладене на білий
аркуш зображення лишилось тим самим. Перевірено попіксельно, жоден
піксель не вийшов за допуск у два рівні з двохсот пʼятдесяти шести.

Оригінали дизайнера НЕ правилися, дефект у них лишається. Якщо колись
перегенеровувати веб-файли з оригіналів, прозорість доведеться
відновлювати знову.
